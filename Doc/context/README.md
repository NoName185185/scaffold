# University Board — контекст проекта

Каноническое описание продукта для людей и агентов. Источники: исходное ТЗ (`Doc/implementation/ProjectOld.md`) и уточнение анонимности (`Doc/implementation/ProjectNew.md`). При расхождении действует **этот файл**.

Как запустить код — корневой [`README.md`](../../README.md). Как устроен каркас сейчас — [`Doc/implementation/`](../implementation/README.md).

## Суть

Веб-портал для студентов одного университета: имиджборд в духе 2ch/4chan со структурой Reddit.

**Доски → треды (посты) → комментарии → голосование.**

Публичный вид — анонимный: читатель не видит, кто написал пост или комментарий, если автор так решил. Внутри системы автор **известен**: в БД всегда лежит `authorId`, чтобы модерация могла разбирать нарушения. Анонимность — это не «нет аккаунта» и не хеш IP, а **сокрытие автора в JSON API**.

Учебный проект (курсовая / диплом, тема Web-portal). Документация и код должны быть объяснимы в академическом SRS: architecture, ERD, use cases, security, testing. Без микросервисов, очередей и прочего, что нельзя коротко защитить на защите.

## Анонимность (актуальная модель)

Старое ТЗ предлагало постинг без регистрации и `authorHash` (например `hash(IP + salt + date)`), плюс запрет хранить то, по чему обычного пользователя можно деанонимизировать. Это **снято**.

Как должно быть:

1. Обычный пользователь **регистрируется и входит** (JWT + bcrypt). Без сессии пост и комментарий не создаются.
2. У поста и комментария флаг `isAnonymous` (на фронте чекбокс «постить анонимно»).
3. В БД всегда сохраняется реальный `authorId`.
4. При сериализации ответа: если `isAnonymous = true`, поле автора **не включается** в JSON.
5. Исключение: запрос от пользователя с ролью `admin` (при необходимости и `moderator`) — автор в ответе виден для разбора жалоб.
6. Роли `moderator` и `admin` — те же аккаунты с полем `role`, не отдельный мир «только модераторы логинятся».

Публичная анонимность сохраняется. Служебная — нет: админ в БД и в своём API видит автора.

## Стек (не менять без отдельного решения)

| Слой | Технологии |
| --- | --- |
| Backend | Node.js, Express |
| ORM / БД | Prisma, PostgreSQL |
| Frontend | Vue 3, Vite, Composition API, `<script setup>` |
| Инфра | Docker Compose: `db`, `backend`, `frontend` |
| Auth (план) | `bcryptjs`, `jsonwebtoken`, `JWT_SECRET` |
| AI (после ядра) | Ollama и/или OpenRouter, обычный HTTP из Express |

Node.js выбран в том числе из‑за простых HTTP-интеграций с LLM.

AI **не** в критическом пути публикации: отдельный модуль/роут, отказ сервиса не блокирует постинг.

## Роли

| Роль | Что делает |
| --- | --- |
| Пользователь | Регистрация, вход, чтение досок, пост/комментарий (в т.ч. анонимно), голос |
| Moderator | Удаление контента, разбор жалоб, баны по `authorId` |
| Admin | Всё модераторское + создание досок, управление ролями, в API видит автора анонимных постов |

Админ-эндпоинты по умолчанию **закрыты**. Сейчас в каркасе `DELETE /api/posts/:id` и `POST /api/boards` открыты всем — это долг, не целевое поведение.

## Состояние каркаса (код на диске)

Ещё **не** сделано то, что описано в New: нет User/JWT, нет `isAnonymous`, фронт без логина и без формы поста.

Есть базовый CRUD без auth и без AI:

- `GET/POST /api/boards`
- `GET/POST /api/boards/:slug/posts`
- `POST /api/posts/:id/vote`
- `POST /api/posts/:id/comments`
- `DELETE /api/posts/:id`
- Vue-лента с голосами, доска захардкожена как `study`

Схема сейчас: `Board`, `Post` (`authorHash?`, `imageUrl?`), `Comment` (`authorHash?`), `Moderator`. Целевая замена: `User` (login, passwordHash, role), у Post/Comment — `authorId` + `isAnonymous`, `authorHash` убрать. Позже — `Ban`, `Report`.

## Куда идём (приоритет)

Перед крупным шагом — короткий план (файлы, роуты, модели), потом код.

1. **Пользователи и JWT** — регистрация/вход, middleware `attachUser`, `requireAuth`, `requireRole`. Зависимости: `bcryptjs`, `jsonwebtoken`. `JWT_SECRET` в `.env` и compose.
2. **Новая анонимность** — схема `authorId` + `isAnonymous`; утилита сериализации; роуты постов/комментариев не светят автора; admin видит.
3. **Фронт auth + форма поста** — вход/регистрация, чекбокс «постить анонимно», убрать хардкод `study`, Vue Router (доски, тред).
4. **Картинки** — multer, тип/размер, volume или S3-совместимое хранилище.
5. **Модерация** — закрыть удаление и создание досок ролями; баны по `authorId`; жалобы (`Report`).
6. **Безопасность** — rate-limit постинга, капча на новый тред, санитизация XSS; SQL закрывает Prisma (ручные fragments проверять).
7. **AI** — `GET/POST /api/ai/moderate`: текст → Ollama/OpenRouter → toxic/ok, опционально и асинхронно.

## Нефункциональные ограничения

- Для публики анонимный пост выглядит без автора; для админа — нет.
- Не тащить IP в фронт и в публичные логи как идентификатор автора.
- Код простой: один backend, один frontend, одна БД.
- Документацию держать в виде, пригодном для отчёта (SRS).
