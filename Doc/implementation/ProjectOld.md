# University Anonymous Board — техническое задание проекта

## Суть проекта

Веб-портал в формате анонимного имиджборда (в духе 2ch/4chan), но со
структурой обсуждений как в Reddit: **доски → треды (посты) → комментарии →
голосование**. Площадка предназначена для внутреннего использования студентами
одного университета.

Ключевая идея: пользователи публикуют посты и комментарии **без регистрации**(Но это не значет),
под временным анонимным идентификатором (хэш, уникальный в рамках треда/сессии,
не раскрывающий личность). Модерация и администрирование, наоборот, требуют
полноценной авторизации — доступны только ролям `moderator` и `admin`.

Это учебный проект (курсовая/дипломная работа, тема "Web-portal"), поэтому
документация должна параллельно соответствовать академическому SRS-шаблону
(architecture, ERD, use cases, security, testing) — держи это в уме при
структурировании кода: она должна быть представима как часть отчёта.

## Технологический стек (зафиксирован, не менять без обсуждения)

- **Backend:** Node.js + Express
- **ORM / БД:** Prisma + PostgreSQL
- **Frontend:** Vue 3 + Vite (Composition API, `<script setup>`)
- **Инфраструктура:** Docker Compose (сервисы: `db`, `backend`, `frontend`)
- **Будущая AI-интеграция:** Ollama (локально) и/или OpenRouter (облако) —
  через обычные HTTP-запросы из Express, отдельным роутом/модулем, не
  встроено в основной flow постинга напрямую (чтобы не блокировать публикацию
  при недоступности AI-сервиса)

Backend выбран на Node.js в первую очередь потому, что интеграция с
LLM-провайдерами (Ollama/OpenRouter) там технически проще и есть больше
готовых SDK/примеров, чем на альтернативах.

## Модель данных (текущая, prisma/schema.prisma)

```prisma
model Board {
  id, slug (unique), title
  posts Post[]
}

model Post {
  id, boardId, title, body, imageUrl?, authorHash?,
  upvotes, downvotes, createdAt
  comments Comment[]
}

model Comment {
  id, postId, body, authorHash?, createdAt
}

model Moderator {
  id, login (unique), passwordHash, role ("moderator" | "admin"), createdAt
}
```

## Что нужно реализовать дальше (по приоритету)

1. **Авторизация модераторов** — JWT + bcrypt поверх модели `Moderator`.
   Middleware `requireAuth` / `requireRole('admin')` для защиты
   административных роутов.
2. **Анонимная идентификация постящих** — генерация `authorHash` на бэкенде
   (например, `hash(IP + salt + date)`), не хранить и не отдавать реальный IP
   на фронт.
3. **Загрузка изображений** — `multer` для приёма файлов, валидация типа/
   размера, хранение в volume или S3-совместимом сторедже.
4. **Модерация**: удаление постов/комментариев модератором, бан по
   `authorHash` (таблица `Bans`, ещё не создана — нужно добавить в схему),
   система жалоб (таблица `Reports`, тоже нужно добавить).
5. **Безопасность**: rate-limiting постинга (`express-rate-limit`), капча при
   создании треда, санитизация ввода от XSS, защита от SQL-инъекций
   (Prisma параметризует запросы по умолчанию, но проверяй ручные fragments).
6. **AI-модуль** (после основного функционала): отдельный роут
   `/api/ai/moderate` — принимает текст поста, отправляет в Ollama/OpenRouter,
   возвращает вердикт (toxic/ok) до публикации. Делать асинхронно/опционально,
   чтобы отказ AI-сервиса не блокировал постинг.
7. **Frontend**: убрать хардкод доски `study`, добавить список досок,
   роутинг (Vue Router) между досками и тредами, форму создания поста/
   комментария, базовый UI для модератора (кнопка удаления, если роль есть).

## Нефункциональные требования, которые нужно держать в голове

- **Анонимность — принципиальное свойство системы**, не просто "нет
  регистрации". Не логировать и не хранить данные, позволяющие
  деанонимизировать обычного пользователя.
- Все админ-эндпоинты должны быть защищены авторизацией — по умолчанию
  считать их закрытыми, а не открытыми.
- Код должен оставаться достаточно простым для объяснения в академической
  документации (это не production highload-система, а учебный проект —
  не переусложняй архитектуру микросервисами, очередями и т.п. без явной
  необходимости).
