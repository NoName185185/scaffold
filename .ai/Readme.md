# .ai — мультиагентный конвейер разработки RUBA AI OS

Инструмент-независимая конфигурация AI-агентов (подход из статьи «Мультиагентная разработка: от хотелок до продакшена», упрощённый: минимум контроля человека — человек одобряет только спецификацию).

## Процесс

```
оркестратор → эпик → спека → [ЧЕЛОВЕК одобряет] → план кода → код → ревью (≤2 попытки)
→ план тестов → тесты → ревью (≤2 попытки) → DevLog + резюме
провал 2-го ревью → возврат к одобрению спеки (человек уточняет её)
```

Точка входа — команда `.ai/commands/ra-feature.md` (в Cursor: skill `/ra-feature`).

## Структура

```
.ai/
├── agents/              # Промпты агентов (один агент — одна ответственность)
│   ├── Template/        # Шаблоны артефактов: EpicSummary, Spec, CodePlan, TestPlan, DevLog
│   ├── epic-writer.md   # Product Owner: эпик и этапы
│   ├── spec-writer.md   # Аналитик: спецификация (единственный документ на одобрение человеком)
│   ├── code-planner.md  # Техлид: план изменений кода
│   ├── developer.md     # Разработчик: код по плану + ruff
│   ├── reviewer.md      # Ревьюер кода и тестов: APPROVED / CHANGES_REQUESTED, лимит 2 попытки
│   ├── test-planner.md  # Техлид тестирования: план тестов
│   ├── test-developer.md# Разработчик тестов: pytest
│   └── devlog-writer.md # Летописец: DevLog.md + резюме человеку
├── commands/
│   └── ra-feature.md    # Алгоритм оркестрации всего конвейера
└── rules/               # Источники знаний для всех агентов
    ├── Architecture.md  # Слои backend/app, правила зависимостей
    ├── CodeStyle.md     # ruff, типы, SQLAlchemy 2.0, Pydantic v2
    ├── TestingHints.md  # pytest, моки, запуск без Docker/сети
    └── BitrixBridge.md  # bump версии PHP-моста product.php
```

## Артефакты

Хранятся в `Doc/Features/<ГОД>/<НОМЕР>_<Kebab-Name>/`:

| Файл | Кто создаёт | Кто одобряет |
|------|-------------|--------------|
| `EpicSummary.md` | epic-writer | — |
| `Spec.md` | spec-writer | **человек** |
| `CodePlan.md` | code-planner | reviewer (косвенно) |
| `TestPlan.md` | test-planner | reviewer (косвенно) |
| `DevLog.md` | devlog-writer | человек читает перед коммитом |

## Принципы

1. **Один агент — одна ответственность** — компактные промпты, понятно кто «накосячил».
2. **Изоляция контекста** — агент получает пути к артефактам, а не пересказ; каждый запуск в чистом контексте.
3. **Человек управляет только через спеку** — правки объёма/поведения → правка Spec.md → перезапуск конвейера.
4. **Лимит 2 ревью-цикла** — дальше конвейер останавливается и возвращается к человеку со сводкой.
5. **Ворота качества автоматические** — ruff и pytest обязательны перед каждым вердиктом ревьюера.
